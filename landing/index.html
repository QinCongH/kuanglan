产品名即产品体验

「框」是收纳，「览」是一览

框边框收纳

每个站点独占一个独立的网页视图容器，页面之间互不干扰：登录态各自保留，缓存可按视图单独清理，跳到站外还会先问你一句。

览一览无余

分组侧边栏 + 顶部快捷栏两级收纳，常用站点常驻左侧，其余收进可随时呼出的悬浮栏。切换是瞬时完成的，视图在后台常驻，不会重新加载。

已实现的能力

它替你管好这几种「开着一堆标签」的场面

下面每一条都对应 v1.4.0 里真实可用的功能，没有规划中的空话。

8 个常驻位，按键即达

侧边栏最多同时常驻 8 个视图，Ctrl + ↑ / ↓ 在它们之间循环切换。视图在后台保持存活，来回切换不会重新加载页面、不会掉登录态。

WebContentsView上限 8免重载

用不到的，收进快捷栏

把视图设为隐藏，它就从侧边栏退到顶部悬浮快捷栏。Alt + Z / Alt + X 显隐，快捷栏内可搜索，点一下就把它捞回侧边栏 —— 位置不够时框览会直接告诉你上限。

悬浮快捷栏支持搜索边缘自动滚动

分组收纳，拖拽归位

按「AI 助手」「开发工具」这样建组管理视图：新建、改名、折叠展开、组内拖拽排序。想挪出某个视图，长按侧边栏图标即可移出。删除分组前需要先清空其中的视图，避免误删。

新建/改名/折叠拖拽排序长按移出

kl:// 一行链接分享配置

任何视图都能复制成一条 kl:// 分享链接（名称、地址、分组打包编码）。对方只要打开框览，应用会自动识别剪贴板里的链接并导入到默认分组 —— 不用发压缩包，也不用对方手敲地址。

一键复制剪贴板自动识别粘贴导入

站点图标自动抓取

填完地址，图标就自己出现了。抓取由主进程代理发起以绕开跨域限制，结果同时写入内存与本地缓存，启动时按并发批量预热 —— 断网或换主题也不会满屏灰方块。

主进程代理双层缓存并发预热

数据放在你自己选的目录

首次启动先让你选数据目录，之后分组、视图与设置都写在该目录的 JSON 文件里，没有账号、没有云端。设置里可随时查看、打开或更换目录，换电脑整个文件夹拷走即可。

无账号本地 JSON目录可迁移

常见问题

几个一定会被问到的

框览是多标签页浏览器吗？
不是。它不会把多个网页拼在同一屏里显示 —— 同一时刻只显示一个视图，每个视图是独立的网页视图容器，在后台常驻。它解决的是「我有 12 个站点每天各开一次」，而不是「我要同时看 3 个页面」。侧边栏就是那 12 个站点的入口。
为什么侧边栏只能放 8 个？
8 是侧边栏常驻视图的硬上限，超过后切换效率会明显下降。放不下的可以设为隐藏，它们会进入顶部快捷栏，随时用 Alt + Z 呼出并搜索；从快捷栏点回侧边栏时如果已满，框览会直接提示你先移出一个。
我的数据存在哪里？会上传吗？
首次启动会要求你选择数据目录，之后分组、视图和设置都写在本地 JSON 文件里，不上传、不需要账号。可以在「设置 → 资源路径」里查看当前目录、直接打开它，或换到新位置。网页本身的登录态由系统内核的会话数据管理，可按视图单独清理。
怎么把一套配置给朋友？
在设置页对任意视图选择「复制分享链接」，会得到一条 kl:// 开头的链接。对方打开框览后会自动识别剪贴板里的这条链接并导入到默认分组；如果没触发自动导入，也可以在顶部工具栏手动粘贴导入。
会自动检查更新吗？
不会。v1.4.0 尚未接入自动更新逻辑，请定期回到本页下载新版本。更新前不需要卸载，直接安装新版即可，数据目录里的配置会保留。
它会不会记录我看了什么？
框览不采集浏览内容，也没有任何统计上报。视图跳转出原域名时会先弹出确认，既是防误点，也是让你知道当前这个框正在把你带向站外。图标抓取走的是第三方 favicon 服务，只包含域名本身。
