# 「框览」资源路径配置功能 — 详细实现文档

> 需求来源：`.agent/需求.md`
> 原始需求：项目启动时，需要新增配置资源路径，首先检测使用配置了资源路径，如果没有配置则弹出配置资源路径窗口，配置后进入主窗口。设置里面可以查看配置的路径，有打开目录，修改目录按钮。配置目录如果目录没有默认给目录创建"默认目录"，配置完成后重新加载页面

---

## 一、需求分析与拆解

### 1.1 原始需求提取

| # | 需求点 | 关键词 |
|---|--------|--------|
| 1 | 项目启动时检测是否已配置资源路径 | 启动检测、条件判断 |
| 2 | 未配置 → 弹出配置窗口（阻塞主窗口） | 模态窗口、引导流程 |
| 3 | 配置后进入主窗口 | 流程衔接 |
| 4 | 设置页面可查看已配置路径 | 设置展示 |
| 5 | 设置页面有"打开目录"按钮 | shell.openPath |
| 6 | 设置页面有"修改目录"按钮 | dialog.showOpenDialog |
| 7 | 配置目录不存在时自动创建"默认目录"子文件夹 | 目录初始化 |
| 8 | 配置完成后重新加载页面 | 页面刷新 |

### 1.2 需求优化与补充

原始需求描述较简略，以下为优化后的完整需求定义：

**1. 资源路径的概念定义**
- "资源路径"是用户指定的本地目录，用于存放框览应用的业务数据文件（如导出的配置、收藏的网页快照等用户产生的资源）
- 该路径与 `app.getPath('userData')` 系统目录不同，是用户可自定义的外部存储位置

**2. 启动流程优化**
- 首次启动（未配置资源路径）→ 弹出配置引导窗口 → 配置完成 → 进入主窗口
- 非首次启动（已配置）→ 检查路径是否有效（目录是否存在）→ 有效则直接进入主窗口 / 无效则提示重新配置

**3. 设置页面增强**
- 新增"资源路径"设置项，位于设置页面的独立 Tab 或"通用"分类下
- 展示当前配置的路径
- 提供"打开目录"按钮（调用系统文件管理器打开）
- 提供"修改目录"按钮（弹出系统目录选择器）
- 修改后自动重新加载页面以使新路径生效

**4. 目录初始化逻辑**
- 用户选择或配置的目录如果不存在，自动创建该目录
- 目录创建后，在目录内自动创建"默认目录"子文件夹作为初始分类

**5. 边界情况处理**
- 用户在配置窗口点击取消/关闭 → 应用退出（首次必须配置）
- 用户选择的目录无写入权限 → 提示错误，要求重新选择
- 修改路径后旧目录数据不自动迁移（用户自行管理）

app.whenReady()

### 2.3 配置引导窗口

使用独立的 `BrowserWindow` 作为模态引导窗口，在主窗口创建前显示：

```ts
// src/main/resource-path-setup.ts

function showResourcePathSetup(): Promise<string | null> {
  return new Promise((resolve) => {
    const setupWindow = new BrowserWindow({
      width: 520,
      height: 400,
      resizable: false,
      minimizable: false,
      maximizable: false,
      frame: false,
      show: false,
      modal: true,
      webPreferences: {
        preload: join(__dirname, '../preload/index.js'),
        sandbox: false
      }
    })

    // 窗口关闭 = 用户取消 = 退出应用
    setupWindow.on('closed', () => {
      resolve(null)
    })

    // IPC：用户提交路径
    ipcMain.handleOnce('setup:resource-path', (_e, path: string) => {
      resolve(path)
      setupWindow.close()
    })

    setupWindow.on('ready-to-show', () => {
      setupWindow.show()
    })

    // 加载引导页面
    if (is.dev && process.env['ELECTRON_RENDERER_URL']) {
      setupWindow.loadURL(`${process.env['ELECTRON_RENDERER_URL']}#setup`)
    } else {
      setupWindow.loadFile(join(__dirname, '../renderer/index.html'), { hash: 'setup' })
    }
  })
}
```

### 2.4 IPC 通道新增

| 通道 | 方向 | 参数 | 返回值 | 说明 |
|------|------|------|--------|------|
| `setup:resource-path` | renderer → main | `path: string` | `void` | 引导窗口提交路径 |
| `setup:select-dir` | renderer → main | — | `string \| null` | 引导窗口选择目录 |
| `setting:resource-path:get` | renderer → main | — | `string \| null` | 获取当前资源路径 |
| `setting:resource-path:set` | renderer → main | `path: string` | `void` | 修改资源路径 |
| `setting:resource-path:open` | renderer → main | — | `void` | 在文件管理器中打开 |
| `setting:resource-path:select` | renderer → main | — | `string \| null` | 弹出目录选择器 |

### 2.5 Preload API 扩展

```ts
// src/preload/index.ts 新增

  submitPath: (path: string) => ipcRenderer.invoke('setup:resource-path', path),

  select: () => ipcRenderer.invoke('setting:resource-path:select')
}
```

### 2.6 渲染进程路由

使用 Vue Router 的 hash 模式区分主页面和引导页面：

| 路由 | 组件 | 说明 |
|------|------|------|
| `/` | `App.vue`（现有主布局） | 主应用界面 |
| `/setup` | `ResourcePathSetup.vue`（新增） | 资源路径配置引导 |

或者更轻量的方案：在 `App.vue` 中通过条件渲染判断是否显示引导界面，无需引入 Vue Router。

**推荐方案：条件渲染**（无需引入路由依赖，与现有架构一致）

```vue
<!-- App.vue -->
<template>
  <ResourcePathSetup v-if="appStore.showSetup" />
  <div v-else class="app-layout" :class="{ 'sidebar-expanded': appStore.sidebarExpanded }">
    <!-- 现有布局 -->
  </div>
</template>
```

但考虑到引导窗口是独立 BrowserWindow，它加载的是同一个 renderer 但需要不同的 UI。使用 hash 路由区分更干净：

**最终方案：hash 路由区分**

在 `App.vue` 的 `onMounted` 中检测 `window.location.hash`：

```ts
const isSetupWindow = window.location.hash === '#setup'
if (isSetupWindow) {
  // 渲染引导界面，不初始化主应用
}
```

    app.setAppUserModelId('com.kuang-lan')

### Step 9：目录初始化逻辑

**文件**：`src/main/database/index.ts`

```ts
export function ensureResourcePath(dirPath: string): void {
  // 确保主目录存在
  if (!existsSync(dirPath)) {
    mkdirSync(dirPath, { recursive: true })
  }

  // 确保默认子目录存在
  const defaultDir = join(dirPath, '默认目录')
  if (!existsSync(defaultDir)) {
    mkdirSync(defaultDir, { recursive: true })
  }
}
```

## 六、边界情况与错误处理

| 场景 | 处理方式 |
|------|----------|
| 首次启动用户关闭引导窗口 | `resolve(null)` → `app.quit()` 退出应用 |
| 选择的目录无写入权限 | `mkdirSync` 抛出异常 → catch 后提示用户重新选择 |
| 已配置的路径被外部删除 | `ensureResourcePath` 自动重建目录和"默认目录"子文件夹 |
| 已配置的路径所在盘符不存在（如 U 盘拔出） | `existsSync` 检测失败 → 弹出提示让用户重新配置 |
| 修改路径时选择与当前相同的路径 | 检测路径相同 → 提示"路径未变更" → 不重新加载 |
| 引导窗口中用户手动输入非法路径 | 前端校验 + 后端 `mkdirSync` 失败时提示 |

## 七、实现优先级与验收标准

### 优先级：P0（核心流程，阻塞应用启动）

### 验收标准

- [ ] 首次启动弹出配置引导窗口，无法跳过
- [ ] 引导窗口可选择目录，确认后进入主界面
- [ ] 引导窗口关闭后应用退出
- [ ] 配置的目录自动创建"默认目录"子文件夹
- [ ] 非首次启动直接进入主界面
- [ ] 已配置路径被删除后启动能自动重建
- [ ] 设置页面可查看当前资源路径
- [ ] 设置页面"打开目录"按钮可在文件管理器中打开
- [ ] 设置页面"修改目录"按钮可更换路径
- [ ] 修改路径后页面自动重新加载
