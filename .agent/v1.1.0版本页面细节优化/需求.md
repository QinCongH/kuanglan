# 桌面应用视图与分组管理需求文档

## 1. 项目概述
本文档旨在规范桌面端 Electron 应用中侧边栏视图管理、顶部快捷栏交互以及设置弹窗中视图/分组管理的详细功能逻辑。重点优化用户添加视图的体验、动画流畅度、数据安全性（二次确认与校验）以及资源路径变更后的实时刷新机制。

## 2. 功能需求详情

### 2.1 侧边栏视图添加交互
- &zwnj;**触发入口**&zwnj;：点击侧边栏分组标题下的“添加视图”。
- &zwnj;**表单默认行为**&zwnj;：
  - 弹出“添加视图表单”模态框。
  - &zwnj;**分组选择字段**&zwnj;：自动默认选中当前触发操作的分组名称。
  - 用户可手动修改分组，但初始状态必须与上下文一致，减少操作步骤。

### 2.2 顶部快捷卡片栏动画
- &zwnj;**显示动画**&zwnj;：
  - 当触发条件满足（如鼠标悬停顶部区域或快捷键触发）时，快捷卡片栏从顶部边缘向下滑入。
  - 使用 `transform: translateY` 配合 `opacity` 实现平滑过渡，建议时长 200ms-300ms，缓动函数 `ease-out`。
- &zwnj;**隐藏动画**&zwnj;：
  - 当触发条件消失（如鼠标移出）时，快捷卡片栏向上滑出并淡出。
  - 建议时长 150ms-200ms，缓动函数 `ease-in`，确保收起迅速不拖沓。

### 2.3 设置弹窗 - 视图管理模块

#### 2.3.1 编辑视图界面优化
- &zwnj;**下拉框样式调整**&zwnj;：
  - 在“编辑视图”表单中，“选择分组”的下拉选择器需去除默认的圆点装饰或自定义标记，保持简洁的文本列表风格，符合桌面端原生UI规范。
- &zwnj;**弹窗头部去色**&zwnj;：
  - 去除“编辑视图”弹窗的顶部高亮颜色

#### 2.3.2 删除视图安全机制
- &zwnj;**二级确认流程**&zwnj;：
  - 点击“删除视图”按钮后，不立即执行删除。
  - 弹出二次确认对话框（Modal），文案提示：“确定要删除视图 [视图名称] 吗？此操作不可恢复。”
  - 仅当用户点击“确认”后，才执行删除逻辑。

### 2.4 设置弹窗 - 分组管理模块

#### 2.4.1 分组展开交互
- &zwnj;**展开图标**&zwnj;：
  - 在分组列表每一项左侧新增展开/折叠图标（如 Chevron Right/Down）。
  - 点击图标可展开该分组，显示其下属的所有视图列表；再次点击则折叠。
  - 默认状态下，分组可保持折叠或根据用户上次操作状态恢复。

#### 2.4.2 删除分组校验与确认
- &zwnj;**前置校验**&zwnj;：
  - 点击“删除分组”时，系统首先检查该分组下是否关联了任何视图。
  - &zwnj;**若存在视图**&zwnj;：阻止删除，弹出错误提示 Toast 或 Alert：“该分组下存在视图，请先清空或迁移视图后再删除分组。”
  - &zwnj;**若为空分组**&zwnj;：进入二级确认流程。
- &zwnj;**二级确认流程**&zwnj;：
  - 弹出二次确认对话框，文案提示：“确定要删除分组 [分组名称] 吗？”
  - 用户确认后，执行删除操作并更新本地数据结构。

### 2.5 侧边栏长按删除进程清理
- &zwnj;**进程销毁**&zwnj;：
  - 执行删除操作时，不仅移除前端DOM和数据结构，必须同步调用 Electron 主进程接口。
  - &zwnj;**核心动作**&zwnj;：销毁该视图对应的 `webviewContent` 实例或 `BrowserView` 进程，释放内存资源，防止后台进程残留导致内存泄漏。

### 2.6 设置弹窗 - 资源路径管理
- &zwnj;**目录修改与刷新**&zwnj;：
  - 用户在“资源路径”设置项中修改目录并保存成功后。
  - &zwnj;**全局刷新**&zwnj;：触发整个应用的资源重新加载机制。
  - &zwnj;**即时生效**&zwnj;：确保当前界面显示的资源列表、缩略图或文件树立即切换为新选定目录下的内容，无需重启应用。

### 2.7 初始化数据结构优化
- &zwnj;**目录初始化逻辑**&zwnj;：
  - 应用首次启动或初始化指定目录时，扫描选中目录。
  - &zwnj;**禁止创建冗余文件夹**&zwnj;：不要在选中目录下自动创建名为“默认目录”或“Default”的子文件夹。
  - &zwnj;**仅生成数据文件**&zwnj;：仅在根目录下生成或读取 `data.json` 配置文件，用于存储视图布局、分组信息等元数据，保持用户目录结构的整洁。
