# 「框览」桌面端工具 UI 设计提示词

> 产品类型：多 WebView 视图聚合管理桌面工具（类似 AI 视图导航台）
> 设计风格定位：**可爱简约风（Kawaii Minimal / Soft Pastel）**

---

## 一、产品定位与设计基调

「框览」的核心使命是把分散在各处的网页视图（ChatGPT、Gemini、Claude、Copilot……）"框"进同一个"览"窗里——名字本身就是产品体验的隐喻：**边框收纳，一览无余**。

设计基调由此确定：**轻盈、柔和、可爱**——像在整理一个精致的手账本，把心爱的网页小工具温柔地收进各自的口袋里，而不是在操控冷冰冰的控制台。

**风格关键词**：柔粉、圆润、柔和阴影、微动效、温暖、治愈感

---

## 二、主题系统（Theme System）

### 1. 主题切换机制

应用支持**双主题切换**：浅色主题（Soft Light）与深色主题（Cozy Dark），默认跟随系统偏好，用户可在设置中手动切换。

```
主题切换实现规范：
- CSS 变量驱动：所有颜色、阴影、边框均通过 CSS 自定义属性定义
- 切换方式：在 :root 上切换 data-theme 属性（data-theme="light" | data-theme="dark"）
- 过渡动画：主题切换时全局 300ms ease-out 过渡（background-color, color, border-color, box-shadow）
- 持久化：用户选择保存至本地存储，下次启动时优先读取用户偏好
- 初始化：启动时依次检测 ① 用户存储偏好 ② 系统偏好(prefers-color-scheme) ③ 兜底浅色主题
```

## 三、视觉令牌系统（Design Tokens）

### 1. 字体 Typography

- **界面标题/品牌字（显示字体）**：圆润几何感字体，如 *Nunito* / *Quicksand*（用于"框览"二字、设置页大标题），传达可爱亲和的工具感。
- **正文字体**：系统默认无衬线（PingFang SC / Inter），保证中文可读性与界面性能。
- **数据/标签字体**：等宽字体（如 *JetBrains Mono*）用于 URL 地址、视图计数、快捷键提示。

字号节奏：12 / 13 / 14（正文）/ 16（小标题）/ 20（页面标题），行高 1.6，字距在标题处略微拉宽（letter-spacing: 0.01em）。

### 2. 布局 Layout

- 圆角统一偏大（12px～16px），营造柔软亲切的视觉感受，卡片边角如小卡片般圆润。
- 卡片/面板使用**柔和阴影**：`box-shadow: 0 2px 12px rgba(0,0,0,0.06)`，不使用玻璃拟态，改用微妙的层次感营造"纸片叠放"的温暖质感。
- 间距系统采用 8px 基准网格（8/16/24/32），保持布局整齐有序。

### 3. 标志性元素 Signature

**"标签绳"侧边栏**：左侧标签栏的每个分组用一条竖向的"标签绳"串联——每组视图有一个圆形彩色标签头（不同分组不同颜色），选中视图的标签头微微弹跳并放大 1.1 倍，同时标签绳上出现一个流动的渐变色小光点，从标签头向下滑向当前选中的视图图标，视觉上暗示"在这个口袋里找到了它"。这是整个产品记忆点的核心。

## 四、页框分组设计（Frame Group System）

### 1. 分组概念

页框（WebView 视图）按**分组**进行组织管理，类似浏览器标签组 / 文件夹的概念。每个分组是一组相关视图的集合，用户可自由创建、命名、排序和折叠分组。

```
分组数据模型：
{
  id: string,              // 唯一标识 (uuid)
  name: string,            // 分组名称，如 "AI 助手"、"工作台"
  icon: string,            // 分组图标 (emoji 或图标名)
  color: string,           // 分组标识色 (从预设色板选取)
  order: number,           // 排序序号
  collapsed: boolean,      // 是否折叠
  createdAt: string,       // 创建时间
  updatedAt: string        // 更新时间
}

视图数据模型：
{
  id: string,              // 唯一标识 (uuid)
  groupId: string,         // 所属分组 ID
  name: string,            // 视图名称
  url: string,             // 视图地址
  icon: string,            // 视图图标 (预设或自定义)
  visible: boolean,        // 是否显示
  order: number,           // 分组内排序序号
  bounds: {                // 窗口位置尺寸（预留）
    x: number, y: number,
    width: number, height: number
  },
  createdAt: string,
  updatedAt: string
}
```

### 2. 分组交互设计

```
侧边栏分组展示：
- 分组头部：[彩色圆点] [分组名称] [折叠箭头 ▸/▾] [更多操作 ···]
- 展开态：显示该分组下所有视图图标列表
- 折叠态：仅显示分组头部，视图列表隐藏
- 默认分组："默认分组"（不可删除，可重命名），始终排在最前

分组操作：
- 新建分组：侧边栏底部「+ 新建分组」按钮，点击弹出内联输入框
- 重命名：右键/更多菜单 → 重命名，内联编辑
- 删除分组：右键/更多菜单 → 删除（需确认，分组内视图移至默认分组）
- 排序分组：拖拽分组头部上下移动
- 更换颜色：右键/更多菜单 → 颜色选择器（8 色预设色板）

视图操作（分组内）：
- 拖拽排序：视图可在同组内拖拽排序
- 跨组移动：拖拽视图至另一分组头部释放
- 添加视图：分组展开时，底部显示「+ 添加视图」入口
```

## 五、文件数据库管理（File Database Management）

### 1. 初始化流程

应用启动时，按以下顺序初始化数据：

```
启动流程：
1. Electron 主进程启动
2. 读取用户数据目录（app.getPath('userData')）
3. 检查数据库文件是否存在
   ├── 不存在 → 创建数据库 + 初始化表结构 + 插入默认分组
   └── 已存在 → 读取并校验数据库版本
       ├── 版本匹配 → 加载数据
       └── 版本不匹配 → 执行迁移脚本 → 加载数据
4. 读取文件目录，扫描预设视图配置（见下文）
5. 通过 IPC 将数据发送至渲染进程
6. 渲染进程接收数据，构建分组与视图列表
7. 加载默认或上次选中的视图
```

### 2. 数据库设计

使用 **SQLite**（通过 better-sqlite3）作为本地数据库，存储在用户数据目录下。

```sql
-- 分组表
CREATE TABLE groups (
  id          TEXT PRIMARY KEY,
  name        TEXT NOT NULL,
  icon        TEXT NOT NULL DEFAULT '📁',
  color       TEXT NOT NULL DEFAULT '#FF8FA3',
  sort_order  INTEGER NOT NULL DEFAULT 0,
  collapsed   INTEGER NOT NULL DEFAULT 0,
  is_default  INTEGER NOT NULL DEFAULT 0,
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 视图表
CREATE TABLE views (
  id          TEXT PRIMARY KEY,
  group_id    TEXT NOT NULL REFERENCES groups(id) ON DELETE SET NULL,
  name        TEXT NOT NULL,
  url         TEXT NOT NULL,
  icon        TEXT DEFAULT '',
  visible     INTEGER NOT NULL DEFAULT 1,
  sort_order  INTEGER NOT NULL DEFAULT 0,
  bounds      TEXT DEFAULT '{}',
  created_at  TEXT NOT NULL DEFAULT (datetime('now')),
  updated_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 应用设置表
CREATE TABLE settings (
  key         TEXT PRIMARY KEY,
  value       TEXT NOT NULL,
  updated_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 数据库版本表
CREATE TABLE schema_version (
  version     INTEGER PRIMARY KEY,
  applied_at  TEXT NOT NULL DEFAULT (datetime('now'))
);

-- 索引
CREATE INDEX idx_views_group_id ON views(group_id);
CREATE INDEX idx_views_sort_order ON views(sort_order);
CREATE INDEX idx_groups_sort_order ON groups(sort_order);
```

### 3. 文件目录与预设视图

应用支持从**预设目录**读取视图配置文件，便于分发和批量导入：

```
文件目录结构：
app-data/
  presets/                     -- 预设视图配置目录
    ai-assistant.json          -- AI 助手预设
    dev-tools.json             -- 开发工具预设
    ...                        -- 其他预设文件
  database.sqlite              -- 主数据库
  config.json                  -- 应用配置（窗口位置、主题偏好等）

预设文件格式 (JSON)：
{
  "version": 1,
  "group": {
    "name": "AI 助手",
    "icon": "🤖",
    "color": "#FF8FA3"
  },
  "views": [
    { "name": "ChatGPT", "url": "https://chat.openai.com", "icon": "chatgpt" },
    { "name": "Claude",  "url": "https://claude.ai",       "icon": "claude" },
    { "name": "Gemini",  "url": "https://gemini.google.com","icon": "gemini" }
  ]
}
```

### 4. 初始化读取文件目录流程

```
文件目录读取流程：
1. 主进程启动，确认数据库就绪
2. 扫描 presets/ 目录下所有 .json 文件
3. 逐一解析 JSON 文件：
   ├── 格式校验（版本、必填字段）
   ├── 查询数据库是否已导入过该预设（按 group.name + views 去重）
   │   ├── 未导入 → 写入数据库，标记为预设数据
   │   └── 已导入 → 跳过（不覆盖用户修改）
   └── 记录导入日志
4. 首次启动时（groups 表为空）：自动导入所有预设
5. 非首次启动：仅导入新增的预设文件，不重复导入
6. 通过 IPC 发送完整数据（groups + views）至渲染进程
7. 渲染进程按分组构建侧边栏 UI
```

### 5. IPC 通信接口

```
主进程 → 渲染进程（初始化推送）：
  'db:init'          → { groups: Group[], views: View[], settings: Record<string, string> }

渲染进程 → 主进程（数据操作）：
  'db:group:create'  → Group                      → Group
  'db:group:update'  → { id, ...partial }         → Group
  'db:group:delete'  → { id }                     → void
  'db:group:reorder' → { id, sortOrder }           → void
  'db:view:create'   → View                       → View
  'db:view:update'   → { id, ...partial }         → View
  'db:view:delete'   → { id }                     → void
  'db:view:reorder'  → { id, sortOrder }           → void
  'db:view:move'     → { id, targetGroupId }       → void
  'db:setting:get'   → { key }                    → string | null
  'db:setting:set'   → { key, value }             → void

渲染进程 → 主进程（文件操作）：
  'fs:import-presets'  → { filePaths: string[] }   → { imported: number, skipped: number }
  'fs:export-config'   → { format: 'json' }        → { filePath: string }
```

## 七、动效与微交互原则

- 动效基于"呼吸/弹跳/流动"的可爱语言：缓慢脉冲、轻柔弹跳、彩色流动是首选，避免生硬的线性移动。
- 所有动效控制在 200~400ms，缓动曲线使用 `cubic-bezier(0.34, 1.56, 0.64, 1)`（弹性缓出），体现活泼而非机械。
- 关键反馈（添加成功、切换视图）用一次性的轻柔弹跳 + 短暂色光完成，不使用持续闪烁。
- 主题切换时全局 300ms ease-out 平滑过渡，避免突兀的闪烁切换。
- 尊重「减少动态效果」系统设置，降级为纯透明度过渡。

## 八、设计克制清单（自我审查）

- 整体只允许一处"高光区"：侧边栏选中视图的弹跳 + 分组色光效，是产品记忆点，其余元素保持安静、柔和。
- 渐变色仅用于强调按钮与主题切换过渡，禁止大面积渐变背景。
- 圆角、字体、间距全局统一，杜绝同一界面出现两套圆角逻辑。
- 可爱≠幼稚：色彩温暖但克制，动效活泼但不幼稚，保持工具类产品的专业底线。
